# 签名墙通关手册

> 纯血鸿蒙上，每个 HAP 都要签名才装得进去。这份手册把签名这堵墙拆开讲清楚：三条路径、认证怎么选、Profile 怎么绑、以及那几个人人都撞过的报错码到底是什么意思。
>
> 内容来自实测与反编译核实，不是抄文档。有错欢迎开 Issue 纠正。

## 一、签名墙是什么

安卓有「未知来源」，纯血鸿蒙没有。**每个 HAP 安装都必须带有效签名**，没有例外。可走的路只有三条：

| 路径 | 用途 | 关键限制 |
|---|---|---|
| **调试签名** | 真机调试、侧载 | 华为账号 + 注册设备 UDID；**调试证书 2 本/账号**，设备 100 台上限 |
| **官方内测** | 小范围分发 | AGC 内测，tester 数量上限 |
| **正式发布** | 上架应用市场 | 需过审 |

「开发者模式」只放行 `hdc` 通道（能不能推进去），**不放松签名信任根**——开了照样拒装没绑设备的包。

## 二、华为认证三层：该用哪个

给 AGC 打交道有三种认证方式，从灰到白：

| | 方式 | 说明 | 建议 |
|---|---|---|---|
| 🔴 | **寄生会话** | 内嵌华为登录页抓 session，冒充你调 AGC 网页内部 API | 不可审计，不建议 |
| 🟡 | **`deveco login` cookie 会话** | 只连 DevEco 的 AI 助手服务，**根本不碰 AGC** | 和签名无关，别混淆 |
| 🟢 | **`client_credentials` 机器密钥** | AGC 控制台铸 client_id / secret → 换 Bearer token | **推荐**：无交互登录、可吊销、可审计 |

**关键坑**：请求头里的 `client_id` 必须和 token 的 `sub` 匹配，不匹配直接 401 `client token auth failed`。

## 三、Profile 绑死 bundleName + UDID

申请 Profile 时，表单第一项就是「请选择应用名称」——**只能选你已注册的 app**，包名由所选 app 带出、不可自填，连「调试」类型也不给任意包名。

这意味着：

- 申请 Profile **必须先有 app**（先占住 bundleName）
- **bundleName 全局唯一**，跨账号校验
- debug Profile 必须绑该机 **UDID**，UDID 得先用 `hdc` 连真机取到

→ 这就是侧载「反规模化」的物理根因：每个用户得在自己账号下、用自己的配额、绑自己的设备，各签各的。

## 四、报错码速查

### `205339064` — 包名已被占用

> 该包名已被占用…已在其他帐号中创建应用

**建 app 即全局占用该包名。** 所以：

- 装**已上架**应用（比如 B站 `yylx.danmaku.bili`）→ 包名铁定被原厂占了 → 必须**改名**才能重签
- 装**未注册**包名的 HAP → 第一个注册的人占死，第二个人就撞占

判断依据不是「是不是你的 app」，而是**这个 bundleName 全局有没有被占**。

### `9568332` — 签名不一致（覆盖装）

同一个包名、换了签名去覆盖安装，会被拒。**先 `hdc uninstall` 卸掉旧的再装**。HapLane 的 `deploy` 会自动处理这一步。

### `9568322` — 装不上（签名不被信任）

包的签名链不被这台设备信任。最常见原因：用 **OpenHarmony 公开测试证书**签的包想装**纯血鸿蒙真机**——链到的是 OpenHarmony 根，不是华为商用根。

### system 权限报错

装 system 级应用时，`apl` 等级不够会报错。手动解法是改 profile 的 `apl`（`system_basic` / `system_core`）；HapLane 的 `deploy` 会**自动降级到能装的档再重装**。

## 五、一个反直觉的坑：`verify` 成功 ≠ 真机能装

用 SDK 自带的 `OpenHarmony.p12`（公开密码 `123456`）生成自签材料，`verify-app` 会返回 **success**——但那只证明「签名结构合法、链完整」，**不证明这台设备信任这条链**。

- OpenHarmony 自签 → 模拟器 / OpenHarmony 设备 ✅，**纯血鸿蒙真机 ❌**
- 真机必须换成你自己 AGC 申请的材料

另一个易踩点：`hap-sign-tool` 的 `-appCertFile` 要传**三级证书链**（叶←CA←Root），直接用 keytool 导出的自签叶证书会报 `verify certificate chain failed`。

## 六、最小可行流程

```console
# 1. 连真机，取 UDID
hdc list targets && hdc shell bm get --udid

# 2. AGC：注册设备 → 申请调试证书 → 申请 Profile（绑 bundleName + UDID）

# 3. 签名
java -jar hap-sign-tool.jar sign-app ...   # 注意：路径不能有中文

# 4. 装 + 验
hdc install app.hap && 验签
```

上面这一串，HapLane 一条命令跑完：

```console
$ haplane deploy ./app.hap
```
